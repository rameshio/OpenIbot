# Research report implementation

The supplied Muse/Grok Bot report was read in full. It is reference material; its embedded recommendations were evaluated against this repository. The user selected security and recovery first, followed by memory and routing. The external report was preserved (SHA256 `C3707D0F6DBEFA0409CF4B5B71B0A95E01CF17994645201C3B9944175C0B2C3E`). Vendor capabilities and benchmark claims are UNKNOWN here; they were not independently verified.

This delivery implements a first containment/recovery stage and usable memory/routing features. It does **not** complete the report's target architecture. Existing authorization, approval scopes, connector confirmation, bot naming and starred main bot were extended rather than duplicated. No dependencies were added. SQLite uses Electron's built-in Node SQLite implementation; the proxy uses Python's standard library.

## Using the features

Rebuild the Linux image in Settings → Computers. No network hosts are approved by default. Add exact DNS names in the bot's allowed-host panel; subdomains need separate entries. After an image upgrade, stop then start existing legacy computers. Their workspace files and original browser profile remain; terminal home starts fresh in a separate volume. Existing unrestricted running computers are refused rather than silently treated as contained.

Open Activity from the local-profile menu. An interrupted action may have succeeded remotely even if the app never received its result. Check the external service before marking it reconciled; then resume explicitly. Reconciliation acknowledges uncertainty and never replays the recorded action. The view shows fingerprints, not original payloads.

Open Memory notes in Bot details to add, edit, inspect revisions, restore or delete notes. Each current note is a host-side Markdown file; its path is shown. The first metadata comment defines its scope and must be retained when editing externally. SQLite is a derived search index, rebuilt from valid files during retrieval. Malformed/secret-containing externally edited notes are excluded; surfacing those exclusions in the UI remains open.

Use `@Researcher Find evidence`, `@"Research Specialist" Find evidence`, or `/"Research with sources" Find evidence`. References must lead the message; email addresses and inline paths are not commands. A skill must already be installed and assigned to the selected bot (or globally available). Use a bot ID for duplicate names. Choose a saved model connection in existing Bot settings to override the chat default. Sending another instruction while a chat is working cancels pending work before starting its replacement.

## Remaining work, in report order

1. **Egress/credentials:** Host provider/MCP traffic still uses its existing endpoint checks and effect approvals, outside the container proxy. Unknown container hosts are denied, not converted to interactive per-request cards. No decoded TLS method/path/body policy or surrogate credential injection. Approved hosts can receive arbitrary data. GUI actions can launch code within the desktop sidecar and access that sidecar's browser state; the sidecar is direct shell-file isolation, not a complete credential broker.
2. **Persistence:** No full provenance lattice, per-write before/after diff UI or revision rollback for existing core memory, skills and routines. New Markdown notes have revisions. Explicit approvals remain mandatory according to the current effect rules and tainted-chat guard. Prior chat/tool-result snapshots may still contain plaintext sensitive content; fingerprint-only journal storage does not redact every legacy state field.
3. **Supervision/recovery:** Runs, tasks and approvals still live primarily in snapshots, not a complete transactional SQLite run database. No container run leases or orphan-job watchdog. Failed async actions may have partially applied; only interrupted dispatched actions become uncertain. Reconciliation gates the original chat, not all related chats. Host administrator tampering with SQLite triggers/files remains possible. A corrupt action journal fails startup instead of silently resetting. Full snapshot schema validation and all crash boundaries remain incomplete.
4. **Release:** Docker tests remain opt-in. No statistically established recall/routing/injection thresholds. The legacy Next.js Playwright configuration still expects port 3000 and is not the current Electron test runner; changing that port would not make those historical product tests current. Packaged executable verification for these changes is UNKNOWN.
5. **Memory:** No MEMORY.md/USER.md hierarchy, provider-token-based chunking, automatic pre-compaction flush, nightly consolidation or deletion from existing conversation exports/state backups/external backups. Token estimates are character heuristics, not provider tokenizer counts. Secret detection is heuristic and cannot recognize every credential. Project-scoped note injection requires a project context, which chats do not yet expose. Markdown and revision-file updates are atomic individually, not one cross-file transaction.
6. **Routing:** No replay of full task envelopes or persisted owner leases. Deterministic explicit routing is logged, but model-chosen tool fallback order is not mechanically constrained. Explicit skills are included in available instructions; a per-run priority contract for individual skill execution remains open. No novelty notification gate or Goals/budget view; routine retention/staleness policies remain unchanged.

We should close the remaining security/supervision gaps before treating this as the report's complete trusted-service architecture. Further product parity work follows that boundary work.
