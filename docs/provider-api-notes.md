# Provider integration notes

Official documentation reviewed on 2026-09-14. This implementation uses native server-side `fetch`; it does not expose provider keys to client bundles or select a paid model automatically. Model catalogs change: enter an exact text-generation model ID supported by the corresponding endpoint and your account. The connection test makes a small billable generation request (up to 512 output tokens, with a 20-second deadline). No live credentials were supplied during implementation; all inference tests use mocked responses and deliberately synthetic fixture IDs.

## Application policy

- Only these five adapters are implemented. OpenRouter, local inference, browser/terminal tools, plugins, schedules, and demonstrations that teach actions remain unavailable.
- There is no model catalog cache or guessed default ID. Successful connection testing authorizes one exact model for each provider. Changing the model requires another test. Auto uses the user-selected default; automatic specialists use that same model. Manual teams preserve explicit model assignments, and every model is checked before the first paid call.
- Plans use a requested JSON object plus server validation instead of assuming every model supports the same structured-output API. Invalid plans stop the run. Delegation is limited to four specialists, two concurrent calls, six calls total, and 180 seconds; retries are user-created attempts, with no automatic retries or fallback provider.
- Text streams are parsed incrementally, including split UTF-8 characters and SSE boundaries. Per-call output is limited to 24,000 characters and aggregate output to 120,000 characters. Missing completion events, refusal, rate limits, network failure, and output truncation do not become successful responses.
- Only provider-reported usage is displayed. Missing fields remain unavailable; a run aggregate is unavailable for a field when any call lacks it. Safe usage received before an explicit provider failure is retained. Cancellation or abrupt disconnection may prevent final usage from arriving. No token costs are estimated.
- Prompts request concrete deliverables and concise public summaries, never hidden chain-of-thought. Activity events describe execution actions. Provider reasoning fields are not forwarded, saved, or placed in downloadable files. This filtering does not claim to classify arbitrary prose a model may put into its ordinary answer field.
- Stop aborts transport and prevents further delegation. Already incurred provider charges are not reversed. Partial text is retained; server process loss cannot resume a run.

## Local credential boundary

Routes require an authenticated HttpOnly, same-site workspace session, an explicit workspace request header, and same-origin loopback access. `IBOT_LOCAL_PASSWORD` must contain at least 16 characters. Environment credentials are unavailable to unauthenticated callers. Credentials entered in settings remain only in server memory; refreshing the page rotates the session, cancels its work, and clears tested connections. Disconnect and lock revoke credentials. API responses include connection metadata, never key values or raw provider error bodies. This local-development boundary is not a hosted multi-user authentication system.

Tests in `tests/provider-adapters.test.ts`, `tests/execution.test.ts`, and `tests/session.test.ts` cover provider stream fixtures, errors and cancellation, graph validation and ordering, manual assignments and limits, authenticated route behavior, environment credential isolation, reload rotation, and disconnect races. Live inference and model/account-specific availability remain unverified.
